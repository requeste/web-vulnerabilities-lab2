# Учебное веб-приложение: уязвимости и их исправление

## Дисклеймер / Educational use only

**Проект намеренно содержит уязвимости и предназначен исключительно для обучения, изучения защищённой разработки и воспроизведения ошибок в собственном локальном стенде.**

Запускайте приложение только в изолированной учебной среде с тестовыми данными. Не размещайте уязвимую версию в открытом доступе и не используйте реальные пароли или персональные данные. Демонстрационные скрипты предназначены только для этого стенда либо систем, на тестирование которых получено явное разрешение владельца. Использование материалов для несанкционированного доступа не является целью проекта.

This repository contains an intentionally vulnerable application for education and defensive security training. Run it only in an isolated lab with synthetic data. Use demonstration scripts only against this lab or systems you have explicit permission to test. Do not deploy the vulnerable version to a public-facing environment.


## Технологии и функции

- Python 3, стандартные модули `http.server` и `sqlite3`.
- HTML и CSS для интерфейса.
- Регистрация и вход пользователя с хранением данных в SQLite.
- Библиотека `requests` для демонстрационных Python-скриптов.

## Демонстрируемые уязвимости

| Уязвимость | Причина и результат | Исправление |
| --- | --- | --- |
| SQL Injection | Формирование SQL-запроса с включением пользовательского ввода в текст запроса позволяет изменить его логику при входе. | Параметризованные запросы: данные передаются отдельно от SQL через заполнители `?`. |
| Broken Access Control | Маршрут `/backup` выдаёт файл `database.db` без проверки прав, позволяя скачать учебную базу. | Закрытие публичной выдачи базы: запрос к `/backup` получает `403 Forbidden`. |

Параметризацию запросов описывает [документация Python sqlite3](https://docs.python.org/3/library/sqlite3.html).

## Локальный запуск

Откройте терминал в каталоге проекта. Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install requests
```

Запустите сервер:

```bash
python3 server.py
```

Откройте в браузере: <http://localhost:8000>.

Используйте только вымышленные учётные записи. Для остановки сервера нажмите `Ctrl+C`.

## Порядок демонстрации

1. Запустите уязвимую версию приложения локально и создайте тестовую учётную запись.
2. Запустите демонстрационные скрипты из второго терминала с активированным окружением. Адрес стенда — `http://localhost:8000`.
3. Зафиксируйте результат проверки входа и возможность получения учебной базы через `/backup`.
4. Остановите сервер и примените соответствующие исправления.
5. Перезапустите приложение и повторите проверки: вход с корректными данными должен работать, SQL-инъекция не должна давать обход входа, а `/backup` должен возвращать `403`.

## Применение исправлений

Patch-файлы показывают изменения между уязвимой и исправленной версиями. Для обсуждавшегося исправления SQL-инъекции:

```bash
git apply --check fix_sql.patch
git apply fix_sql.patch
```

Команды выполняются из корня репозитория для версии исходников, к которой подготовлен патч. Остальные исправления применяются аналогично с соответствующим именем файла. Если изменения уже внесены, повторно применять патч не требуется.
